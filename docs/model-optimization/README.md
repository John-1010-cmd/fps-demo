## 3. 本次修订解决的问题

1. 单一版本化 spec 与统一命名取代工作区、docs、多种文件名并列“权威”。
2. 区分工具的脚手架/描述符与真实产物：相机初猜不等于标定，landmark 网格不等于实测，烘焙计划不等于 PNG。
3. 坐标显式分层：人物 rig-local 面向 +Z、左为 +X；展示经 Y 轴旋转 π 面向 -Z、左为 -X。原画的左臂红章不能套用未转换的插件 G7。
4. 删除写死 PASS 分数、历史全绿勾选、固定 176 帧与五帧动画假阳性；每个验收对应可失败的实测和图片。
5. 修复 PMREM 空场景、暂停不归 T-pose、线框材质泄漏、双手持枪滑步、武器预算热替换等执行漏洞。
6. 规范重开流程：用户已自行 stash；本会话不恢复旧实现。规划/新交接文档需单独保留，原图与 ignored 缓存分别处理。
7. 二次复审补齐真实 pass ID、模板预算/评分覆盖、终态脚本的固定 state 路径与跳过规则，避免 next 卡住或遗漏视觉门禁。
8. 明确临时姿态/蒙皮预检与最终 rig 的先后、GLB 独立负例、投影姿态失效重烘焙、异步全程观察及合批后分解的冻结边界；删除 SWAT 残留旧挂载表述。

## 4. 技术路线修正的确认边界

原规划将程序化骨骼字典直接称为插件 `skin.joints` 的等价物，同时要求原生 G12 全绿，这与本机插件契约不兼容。

**D-01已确认（2026-10-01）**：用户明确“允许内部生成GLB”。骨架仍由代码构建，不引入外部人物或骨骼资产；增加一次**本项目自生成 rig GLB 的导出/读取校验**，由插件读取真实 joint order、逆绑定与剪辑，再验证与程序化运行时对应。GLB 只作验证中间件，不替代代码建模或作为 demo 模型源。具体前置和失败处理见总规划 D-01。

这是本次技术修正，已于**2026-10-01由用户确认**，不回填成“2026-09-27 用户已确认”。授权限内部GLB验证；不引入外部模型，不改变demo加载方式，也不代表M0或原生G12已经通过。实际导出/读取/对应与采样仍须在M0样例中验证，失败时报告，不自动改成降级验收。
